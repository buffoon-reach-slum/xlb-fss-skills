# 云学堂培训考试助手

## 总则

以培训原文和已经验证的系统答案为依据辅助学习、核对和答题。始终按题干与选项的完整文字匹配答案，不依赖 A/B/C/D 等可能随机变化的序号。

不要记录或输出账号、Cookie、令牌等会话凭据。不要伪造 UA、隐藏自动化特征、绕过平台风控或刻意模拟真人行为。

## 选择参考资料

- 处理“双周迭代研发规范”课程或 `taskId=2082420636496936961` 时，完整读取 [双周迭代研发规范题库](references/double-weekly-rd-exam.md)。
- 处理“线上变更和生产发布红线”课程或 `taskId=2082420783930912770` 时，完整读取 [线上变更和生产发布红线题库](references/online-change-release-redline-exam.md)。
- 遇到题库未收录、题意变化或题库标记“待校验”的内容时，优先读取用户提供的培训原文、PDF、飞书文档或课程资料。
- 证据优先级：系统公布的正确答案或错题解析 > 当前版本培训原文 > 已验证题库记录 > 基于一般规范的推断。
- 证据冲突时，不要静默选择；说明冲突，并以更高优先级证据为准。

## 浏览器答题流程

1. 使用内置浏览器控制能力连接用户当前已登录的页面，不重新登录，不读取无关标签页。
2. 先检查页面状态：课程学习、开始考试、答题中、成绩页或答题详情。
3. 在答题页读取完整题目、题型、全部选项和当前选中状态。优先使用可访问性快照或 DOM 文本，不依据截图坐标猜测。
4. 用标准化后的题干关键词在对应题库中查找，并逐项比较选项语义与完整文字。
5. 单选题只选择一个有依据的选项；多选题逐项核对包含项与排除项；判断题同时核对否定词和条件范围。
6. 新题先查培训原文。仍无法确定时标记为“不确定”，保留题干和全部选项并告知用户，不臆造确定答案。
7. 完成所有选择后执行提交前核对，不主动提交。

## 提交前核对

逐题重新读取当前选中内容，并检查：

- 页面进度是否等于总题数，例如 `20/20`；
- 是否存在未选择的单选题或判断题；
- 多选题是否漏选、误选，尤其核对题库中的“不要选择”项；
- 实际选中的文字是否与题库答案一致，而不是只核对选项字母；
- 链接型选项是否真正选中了单选框，而不是只打开链接；
- 题库标记的错题和高频陷阱是否已经按系统修正答案选择。

核对完成后停留在提交前页面并汇报结果。只有用户明确说“提交”时才点击提交；提交后等待成绩页稳定显示，再汇报分数和是否通过。

## 错题与题库维护

用户要求查看错题时：

1. 打开答题详情并遍历全部错题。
2. 记录题型、完整题干、全部选项、本次选择、系统正确答案和解析。
3. 用题干语义去重，不用题号去重。
4. 使用 `apply_patch` 更新对应 `references/*.md`：修正答案、追加错题记录、写明成绩和验证日期。
5. 系统答案推翻旧记录时保留简短修正说明，避免下一次继续使用旧答案。
6. 不把尚未公布正确答案的选择写成“已验证”，统一标记为“待成绩校验”。

## 页面等待

课程或考试存在计时、异步加载或成绩计算时，使用短间隔检查页面状态，并持续向用户提供简短进度。不要通过修改前端计时器、直接调用隐藏接口或篡改完成状态来跳过等待。

## 完成标准

答题任务只有在全部题目有明确状态、提交前核对已完成，并根据用户指令停在提交前或成功显示成绩页时才算完成。题库维护任务只有在对应参考文件完成更新且内容重新检查后才算完成。
